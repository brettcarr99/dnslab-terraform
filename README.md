# dns-lab

A Terraform-managed DNS lab in AWS that stands up a complete, self-contained recursive
DNS resolution chain — root, TLD and second-level authoritative servers, a recursive
resolver pointed at the lab's own root, a hidden primary feeding the authoritative
servers by AXFR, and a client generating synthetic query traffic.

Nothing in the lab is static: a zone-churn generator rewrites delegations and A records
every five minutes, and the client fires queries at the resolver, so serials move and
caches turn over on their own.

## Architecture

Six `t3.micro` EC2 instances in one VPC and subnet, each with a static private IP:

| IP | Name | Role | Software |
|---|---|---|---|
| `10.0.1.10` | `dns-lab-root` | Authoritative for `.`, delegates `lab.` | BIND, AXFR slave of dnsmaster |
| `10.0.1.11` | `dns-lab-tld` | Authoritative for `lab.`, delegates `example.lab.` | BIND, AXFR slave of dnsmaster |
| `10.0.1.12` | `dns-lab-sld` | Authoritative for `example.lab.` (`www`/`mail`/`test`) | BIND, AXFR slave of dnsmaster |
| `10.0.1.13` | `dns-lab-resolver` | Recursive resolver using lab root hints | Unbound |
| `10.0.1.14` | `dns-lab-client` | Query generator | bind-utils + `dns-traffic-gen` |
| `10.0.1.15` | `dns-lab-dnsmaster` | Hidden primary for all three zones | BIND |

```
client ──queries──▶ resolver ──┬──▶ root (.)          ◀─┐
                               ├──▶ tld (lab.)        ◀─┤ AXFR + NOTIFY
                               └──▶ sld (example.lab.)◀─┤
                                       dnsmaster (hidden primary) ─┘
```

**Hidden primary.** `dnsmaster` is `type master` for `.`, `lab.` and `example.lab.`; the
root, TLD and 2LD servers are `type slave` and pull each zone over AXFR. Transfers are
authenticated with a shared TSIG key (`dns-lab-transfer`, hmac-sha256) generated by
`random_id.tsig_key` and templated into all four BIND configs. `dnsmaster` `also-notify`s
each slave, so edits propagate immediately.

**Zone churn.** `/opt/dns-update-gen.sh` on dnsmaster runs every 5 minutes from cron and
issues TSIG-authenticated `nsupdate` calls that add and remove delegations and A records
across all three zones. Log: `/var/log/dns-updates.log`.

**Query traffic.** `dns-traffic-gen` on the client (`/usr/local/bin`, docs at
`~brettcarr/dns-traffic-gen.md`) sends queries to the resolver. Defaults to 100 queries at
100 ms; `-n 0` runs forever, `-i` sets the interval in ms, `-v` is verbose.

**Resolver.** Unbound with a one-line custom root hints file pointing `.` at the lab root
server instead of the real internet roots. DNSSEC validation is disabled
(`module-config: "iterator"`) because the lab zones are unsigned.

**Public names.** Cloudflare A records for `rootdns`, `tlddns`, `2lddns`, `resolver`,
`client` and `dnsmaster` on `pwei.uk` (TTL 60, unproxied) are managed alongside the AWS
resources so public hostnames track the instance public IPs.

## Prerequisites

- Terraform (state was last written by 1.15.2)
- AWS credentials for the target account, and an existing EC2 key pair
- An Amazon Linux 2 AMI ID valid in the target region (the user-data scripts are
  `yum`/`amzn2`-shaped)
- A Cloudflare API token with `Zone:DNS:Edit` on the zone, plus the zone ID

## Configuration

`terraform.tfvars` is gitignored. Required:

```hcl
ami_id               = "ami-..."            # region-correct Amazon Linux 2
key_name             = "my-keypair"
cloudflare_api_token = "..."
cloudflare_zone_id   = "..."
notification_email   = "me@example.com"
ssh_allowed_cidr     = "203.0.113.4/32"     # strongly recommended — default is 0.0.0.0/0
```

Optional overrides: `aws_region` (`us-east-1`), `instance_type` (`t3.micro`),
`vpc_cidr` (`10.0.0.0/16`), `subnet_cidr` (`10.0.1.0/24`).

## Usage

```bash
terraform init          # first time or after provider changes
terraform plan          # preview changes
terraform apply         # deploy / update
terraform destroy       # tear down everything
```

Syntax-check the user-data scripts locally (they need a running EC2 instance to actually
execute):

```bash
for f in user_data/*.sh; do bash -n "$f"; done
```

Each instance publishes "setup complete, rebooting now" to the
`dns-lab-notifications` SNS topic as its last user-data step — **confirm the email
subscription after the first apply** or nothing is delivered.

## Verifying the lab

Allow roughly two minutes for user-data plus a reboot, then:

```bash
terraform output servers
terraform output test_commands
```

From the resolver:

```bash
dig @127.0.0.1 www.example.lab A      # full recursive lookup through the lab chain
dig @10.0.1.10 lab. NS                # root -> TLD delegation
dig @10.0.1.11 example.lab. NS        # TLD -> 2LD delegation
dig @10.0.1.12 www.example.lab. A     # 2LD authoritative answer
```

Useful logs: `/var/log/user-data.log` on any node, `/var/log/dns-updates.log` on
dnsmaster.

## Operational notes

- **User-data replaces instances.** Every instance sets
  `user_data_replace_on_change = true`, so *any* edit to a `user_data/*.sh` script or to a
  templated value replaces the instance rather than rebooting it. Changing a shared value
  such as `subnet_cidr` replaces all six.
- **Static private IPs** come from `cidrhost(var.subnet_cidr, N)` in `locals`, so they are
  known at plan time and can be templated into scripts before the instances exist. Hosts
  `.10`–`.15` are reserved for the lab.
- **Slave startup race.** There is no `depends_on` between dnsmaster and its slaves;
  `root.sh`, `tld.sh` and `sld.sh` poll `nc -zw3 <dnsmaster> 53` for up to five minutes
  before starting `named`, then start anyway and let AXFR retry.
- **S3 script bucket** `dns-lab-scripts-<account_id>` (`force_destroy = true`, all public
  access blocked) holds `chronicled-install.sh`, pulled at boot with `aws s3 cp`. Updating
  that file changes only the S3 object — it does not change any `user_data`, so instances
  are not replaced and will not re-run it until they are next rebuilt.
- **Maintenance cron** on all six nodes: `yum update -y` daily at 02:00, reboot Mondays at
  03:00. dnsmaster also runs the zone update generator every 5 minutes.
- **Local state only.** `terraform.tfstate` lives in the repo root (gitignored), with no
  remote backend or locking. Losing it orphans six instances and a VPC, and it holds the
  TSIG secret in plaintext.
- Providers are pinned: `aws 5.100.0`, `cloudflare 4.52.7`, `random 3.9.0`. Cloudflare
  provider v5 renames `cloudflare_record` to `cloudflare_dns_record` and changes attribute
  names, so a major bump means rewriting `cloudflare.tf`.

## Security

This lab is deliberately permissive inside the VPC and must stay fenced in:

- Unbound uses `access-control: 0.0.0.0/0 allow`, and BIND listens on `any` with
  `allow-query { any; }`. The only thing stopping a publicly reachable open resolver is the
  security group restricting port 53 (TCP and UDP) to `vpc_cidr`. **Do not widen that
  ingress rule.**
- `ssh_allowed_cidr` defaults to `0.0.0.0/0`; set it to your own address in
  `terraform.tfvars`.
- Amazon Linux 2 reached end of life in June 2025. Moving to AL2023 means reworking package
  names and systemd units across all six user-data scripts.
- `user_data/dnsmaster.sh` hardcodes `10.0.1.15` and `10.0.1.10/.11/.12` in the update
  generator (and the client README repeats lab IPs), bypassing the `cidrhost` templating —
  changing `subnet_cidr` will silently break the update generator while everything else
  moves.
